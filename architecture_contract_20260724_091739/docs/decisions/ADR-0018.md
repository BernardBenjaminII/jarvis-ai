# ADR-0018 — Canonical Constitutional Test Fixtures

**Status:** Accepted

**Date:** 2026-07-20

**Supersedes:** None

**Superseded by:** None

---

# Title

Canonical Constitutional Test Fixtures

---

# Context

Genesis has reached the point where multiple certified constitutional
subsystems depend upon one another.

Examples include:

- Executive
- Reasoning
- Planning
- Memory
- Knowledge
- Experience

Each subsystem defines immutable public contracts that become certified
through verification.

Historically, subsequent phases manually reconstructed these constitutional
objects inside their own test suites.

Example:

```
ReasoningSession(...)
ReasoningSessionMetadata(...)
ReasoningSessionId(...)
```

Although functionally correct at the time of creation, these duplicated
fixtures create architectural drift.

When constitutional contracts evolve, manually constructed fixtures become
incorrect while the contracts themselves remain valid.

The Genesis II-A2 certification process exposed this weakness.

The lifecycle implementation remained correct.

The failures originated from duplicated fixture assumptions regarding:

- identifier construction
- metadata construction
- default revision values

The defect existed in the tests—not the certified contracts.

This class of failure is entirely preventable.

---

# Decision

Every certified constitutional subsystem SHALL expose a canonical fixture
library.

Subsequent phases SHALL construct constitutional objects exclusively through
these fixtures.

Manual reconstruction of constitutional objects inside individual test suites
is prohibited once a canonical fixture exists.

---

# Canonical Fixture Layout

Each constitutional subsystem shall expose:

```
tests/
    fixtures/
        __init__.py
        <subsystem>.py
```

Example:

```
tests/
    fixtures/
        reasoning.py
```

---

# Example

Rather than:

```python
session = ReasoningSession(
    session_id=...,
    metadata=...,
    revision=0,
)
```

tests shall instead use:

```python
session = make_reasoning_session()
```

or

```python
session = make_reasoning_session(
    state=ReasoningSessionState.REVIEW
)
```

---

# Required Fixture Capabilities

Canonical fixtures shall provide:

- deterministic identifiers
- deterministic metadata
- deterministic timestamps (where applicable)
- constitutional defaults
- optional overrides
- immutable object construction

Fixtures shall never bypass constitutional validation.

---

# Fixture Source of Truth

Fixtures SHALL derive directly from certified constitutional contracts.

They SHALL NOT duplicate constructor logic.

They SHALL NOT reproduce validation rules.

They SHALL invoke the same public constructors available to production code.

---

# Verification

Each fixture library shall possess its own certification suite.

Verification shall confirm:

- valid constitutional construction
- deterministic output
- immutable objects
- contract compliance
- absence of duplicated fixture implementations

---

# Constitutional Dependency Chain

Certified constitutional layers shall evolve according to the following
pipeline:

```
Certified Contracts
        │
        ▼
Canonical Fixtures
        │
        ▼
Verification
        │
        ▼
Implementation
        │
        ▼
Certification
```

Implementation SHALL NOT precede verified constitutional fixtures.

---

# Engineering Standard

Every constitutional subsystem shall eventually contain the following
structure:

```
contracts/
    immutable public contracts

fixtures/
    canonical construction helpers

verification/
    certification suites

implementation/
    subsystem behavior

docs/
    architectural rationale
```

This structure becomes the standard organizational model for Genesis.

---

# Consequences

Positive:

- Eliminates duplicated fixture logic.
- Prevents architectural drift.
- Simplifies subsystem evolution.
- Reduces maintenance cost.
- Improves certification reliability.
- Encourages constitutional consistency.
- Enables deterministic regression testing.

Negative:

- Requires creation of fixture libraries before dependent phases.
- Adds one additional certification target per subsystem.

These costs are considered acceptable due to the substantial long-term
reduction in maintenance complexity.

---

# Constitutional Principle

A certified constitutional contract is the single source of truth.

Canonical fixtures exist solely to construct valid constitutional objects from
that source of truth.

Tests verify behavior.

Fixtures construct validity.

Contracts define reality.

These responsibilities shall remain permanently separated.
